# Proposal

## Why

Issue #1 已确认：控制插件固定读取“更多”按钮的 `__VUE__[0]`，桥接缺失时即使真实菜单组件仍然存在，也会静默遗漏“重启 QQ”。需要保证用户打开“更多”菜单时，只要原生“设置”仍可用，重启入口就不会因桥接缺失、排列变化或组件重建而丢失。

## What Changes

- 按当前“更多”按钮及菜单能力定位真实 Vue 组件，不再固定依赖 `__VUE__[0]`。
- 复用 QQ 的菜单数据和渲染，在“设置”下方保持唯一的“重启 QQ”，处理组件暂不可用、菜单重建与重复打开。
- 找不到可用菜单时提供明确错误信息，并允许后续组件就绪或再次打开菜单时重新处理，不静默永久遗漏。
- 验证 lite-tools 隐藏“锁定”“退出账号”的真实组合场景；不修改 lite-tools 或 LiteLoader。
- 同步安装器内嵌插件与插件发布压缩包。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `portable-lifecycle`：补充重启菜单入口在桥接缺失、组件重新创建、重复打开及其他菜单项隐藏时的可用性与幂等性要求。

## Impact

- 主要实现范围为 `assets/plugins/qqportable_settings/src/renderer.mjs`，通过现有 `build.ps1` 更新安装器资源与插件压缩包；同步开发文档和主规格。
- 保持 Windows 10/11 x64、.NET Framework 4.8 和单个安装器 EXE；不新增运行时依赖，菜单继续由 QQ 负责布局与高 DPI 渲染。
- 重启调用链、Windows Job 所有权、进程清理、开机自启、设置程序、配置格式、安装目录规则与聊天数据处理全部保持不变。
- 不增加独立重启按钮、托盘图标、遥测、覆盖升级或额外插件；不发布版本、不关闭 issue，除非用户另行要求。
- 已确认的是桥接缺失会导致遗漏入口；lite-tools 开关与桥接缺失的因果关系仍未知，本变更不以该推断作为修复前提。
